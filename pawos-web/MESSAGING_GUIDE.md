# PawOS messaging guide

## Product description

PawOS is an AI Development Operating System that helps developers plan and carry out supported engineering tasks. Describe the work, review proposed steps when shown, and check the result PawOS reports.

## Product experiences

- **Desktop:** Windows app for supported local projects, development tools and environment workflows. Actions depend on installed tools, plan and permissions.
- **CLI:** terminal companion that works from the local folder where it is started. Describe only CLI capabilities confirmed in its guide; do not imply it has every Desktop feature.
- **Web:** browser-based Chat and Code. Code works with connected GitHub repositories. Web does not access a visitor's local files, terminal or desktop.

## Writing rules

- Name the experience, plan or connection when it changes what a user can do.
- Say “supported” when an action depends on a runtime, provider, account or setup.
- Describe plans, approvals, checks and reports as they work; do not promise a successful fix, deployment or pull request.
- Direct visitors to the current in-app billing screen for account-controlled top-up amounts and rates. Enterprise Autonomous Ticket System usage follows its pass-through provider terms.
- Explain Web, Desktop and CLI boundaries plainly. Do not imply shared capabilities where they differ.
- Prefer concrete verbs and short sentences. Avoid generic claims about transforming work, universal integrations, guaranteed outcomes or future capabilities presented as shipped.
- Keep calls to action specific to their destination, such as “Open PawOS Web,” “Compare plans,” or “Contact sales.”
